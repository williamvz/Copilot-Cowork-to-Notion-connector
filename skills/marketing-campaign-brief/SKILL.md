Help the user turn a rough idea or a pile of notes into a clean, complete marketing campaign brief that lives in Notion.

## First, anchor to how this team already works

- Search Notion for existing campaign briefs or a "campaign" / "briefs" database. **Reuse the structure you find** — the same headings, the same database, the same properties (Status, Owner, Launch date, Channels, Budget). Don't impose a generic template if the team already has one.
- If a briefs database exists, create the brief as a new entry in it and fill its properties. If briefs are free-form pages, create a page under the same parent. Ask where it should live if it's ambiguous.

## Gather the essentials (ask for what's missing)

Work from whatever the user already gave you, then fill gaps with a few crisp questions. A strong brief covers:

- **Campaign name** and one-line summary
- **Objective** — the business outcome, not the activity (e.g. "300 SQLs", not "run ads")
- **Target audience / segment**
- **Key message & positioning** — the single most important thing to land
- **Channels** — where it runs (email, social, paid, events, web, PR…)
- **Timeline** — kickoff, key milestones, launch date, end date
- **Budget** — if relevant
- **Success metrics / KPIs** — how you'll know it worked
- **Owner and contributors**
- **Assets & links** — creative, landing pages, related docs (link to existing Notion pages where possible)
- **Dependencies / risks**

Don't interrogate the user — ask for the few highest-value missing pieces, and mark anything still open as `TBD` in the brief so it's visibly unfinished rather than silently wrong.

## Write a brief that's actually usable

- Lead with Objective and Key message — the things people skim for.
- Use clear headings and short, scannable sections; use a checklist for deliverables and a simple table for the timeline/milestones.
- Set database properties (Status, Owner, Launch date, Channels) to match — don't just bury them in body text.
- Link related Notion pages instead of duplicating their content.

## Before you create it

Show the user a quick outline of what you're about to create and where, confirm, then create the page. After creating, share the link and point out anything still marked `TBD` so they know what to finish.
